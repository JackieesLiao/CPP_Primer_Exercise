## 7.8：read 与 print 的引用为何不同

`read` 需要修改对象，因此使用 `Sales_data&`；`print` 只读取对象，使用 `const Sales_data&`，既避免复制又允许传入常量对象。流本身会改变状态，因而流参数不能是常量引用。

## 7.10：嵌套 read 的条件

`read(read(cin, data1), data2)` 先读取第一条，再把返回的同一个流传给外层读取第二条。整个表达式返回该流，`if` 检查第二次读取后的流状态；第一次读取失败时流已失败，第二次也无法正常提取。

## 7.16：访问说明符

`public`、`private`、`protected` 在类内可以多次出现，位置可自由安排，每个说明符作用到下一个说明符或类结尾。对外接口通常设为 `public`；需要保护的内部状态和实现细节通常设为 `private`。

## 7.17：class 与 struct

类定义中默认成员访问权限不同：`class` 默认 `private`，`struct` 默认 `public`；默认继承访问权限也分别为 `private` 和 `public`。显式写出访问说明后，二者的类功能相同。

## 7.18：封装

封装把实现细节藏在受控接口后面。调用者不必依赖数据存储方式，类作者也更容易维护状态约束；实现可以在接口兼容的前提下调整。

## 7.19：Person 的公开和私有部分

构造函数、读取姓名和地址的成员函数作为公开接口；姓名和地址字段设为私有。[ex7_21_22.cpp](ex7_21_22.cpp) 展示这种设计。返回常量引用时，调用方不能修改字段，且必须注意引用不能比所属 `Person` 对象活得更久。

## 7.20：友元的作用与代价

友元适合需要直接访问私有实现、又不适合作为成员的少数函数，例如依赖流在左侧的输入输出函数。它能避免公开只为辅助函数准备的访问器，但会增加友元与类实现之间的耦合；友元关系不是自动对称或传递的。

## 7.30：显式使用 this 的取舍

`this->member` 可以强调访问当前对象的成员，并解决局部名字遮蔽成员的情况；在一般非模板成员函数中无歧义时直接写成员名更简洁。显式 `this` 不能改变成员的访问权限或对象生命周期。

## 7.33：类外定义的返回类型

类外定义时，出现在 `Screen::size` 之前的返回类型还不在类作用域中，因此应写 `Screen::pos Screen::size() const`；同时类内要先声明该成员。函数体中的 `height`、`width` 则按成员查找。

## 7.34：把类型别名移到类尾

`pos` 若在此前已用于成员声明的参数或类型，则把别名移到类末尾会使这些声明处的类型名不可用；若外层碰巧存在同名类型，后续重新定义还可能改变含义并使程序不合法。类型别名应在首次用于声明之前定义。

## 7.35：类作用域中的 Type 与 initVal

类外定义的返回类型 `Type` 位于 `Exercise::setVal` 之前，找到的是外层的 `string` 类型别名，与类内声明的 `double` 返回类型不符。应写 `Exercise::Type Exercise::setVal(Type parm)`。参数表和函数体处于类作用域：参数 `Type` 是类内 `double`，`initVal()` 也是类的成员。将 `double` 结果赋给 `int val` 可能丢失小数，应按需求统一类型。

## 7.36：成员初始化顺序

成员按**声明顺序**初始化，不按初始化列表书写顺序。题中 `rem` 先于 `base` 声明，所以 `rem(base % j)` 会读取尚未初始化的 `base`。可将声明顺序改为 `int base, rem;` 并保持 `base(i), rem(base % j)`，或用参数 `i % j` 初始化 `rem`；两者都要求 `j != 0`。

## 7.37：选择构造函数

`first_item(cin)` 调用输入流构造函数，其值取决于输入及读取是否成功；`next` 调用无需实参的默认构造，书号为空、数量和金额为 0；`last("9-999-99999-9")` 调用字符串构造，书号为给定值，数量和金额为 0。

## 7.38–7.39：默认流参数

可以声明 `Sales_data(std::istream &input = std::cin);`，这允许不传参数时读取标准输入。但如果字符串构造函数也为它的所有参数提供默认值，那么无参构造时两个候选都可用，调用有歧义；应只保留一个无参调用路径。

## 7.43–7.45：没有默认构造函数的成员

`NoDefault` 只接受一个 `int`，所以 `C` 的默认构造要在初始化列表明确构造该成员，例如 `C() : member_(0) {}`，见 [ex7_40_45.cpp](ex7_40_45.cpp)。`vector<NoDefault> values(10)` 需要默认插入 10 个元素，因而不合法；`vector<C> values(10)` 合法，因为 `C` 的默认构造提供了成员初值。

## 7.46：判断默认构造的说法

(a) 错：类没有用户声明构造函数时，编译器可能隐式声明默认构造函数；该函数仍可能被定义为删除。(b) 错：所有参数都有默认实参的构造函数也可作为默认构造函数。(c) 可作为设计原则：若不存在有意义的默认状态，可不提供默认构造，但应权衡容器等使用需求。(d) 错：只要类用户声明了其他构造函数，编译器通常不会再隐式声明默认构造函数；合成默认构造也不保证将每个内置成员变为 0。

## 7.47：字符串构造函数是否 explicit

倾向加 `explicit`：把任意字符串自动当成销售记录容易隐藏错误。代价是调用者需要写显式构造，失去部分简洁性。如果业务明确把书号字符串视为销售记录，并愿意接受这种转换，也可以不加。

## 7.48：直接初始化与 explicit

题中的 `item1(null_isbn)` 和 `item2("9-999-99999-9")` 都是直接初始化。无论单字符串构造函数是否声明为 `explicit`，这两个写法都可调用它；后者先将字面量转换成构造函数参数所需的 `string`。`explicit` 主要禁止相应的隐式转换和复制初始化。

## 7.49：不同 combine 参数

假设字符串构造函数不是 `explicit`：按值参数可以用字符串构造临时 `Sales_data`；非 `const` 左值引用不能绑定该临时对象，因此调用失败；常量引用可绑定临时对象。第三个声明把成员函数标为 `const`，但真正的 `combine` 需要修改当前记录，不能按原义实现；它还返回非常量引用，不能直接从常量成员函数返回 `*this`。若构造函数是 `explicit`，三个调用都需要显式构造实参。

## 7.50–7.51：决定哪些单参数构造应 explicit

`Person` 的仅姓名和输入流构造在 [ex7_21_22.cpp](ex7_21_22.cpp) 中均标为 `explicit`，避免意外转换。`vector` 的单个大小参数构造也应避免把整数隐式变成容器；`string` 从 C 风格字符串转换则是常见且有意支持的便利转换。最终决定取决于接口语义与误用风险。

## 7.52：聚合初始化的版本差异

按本书 C++11 规则，第二章版本的 `Sales_data` 有类内初值，不是聚合，题中的三项花括号初始化没有匹配构造函数。可增加接受书号、册数和单价的构造函数，并计算 `revenue = count * price`。C++14 起聚合规则变化，某些版本可按成员顺序接受该初始化，但第三项会直接初始化销售额为 `15.99`，不是自动计算 `25 * 15.99`；语言版本与业务含义都需检查。

## 7.53–7.55：字面值类与 constexpr

[ex7_53_58.cpp](ex7_53_58.cpp) 实现 `Debug` 的 `constexpr` 构造和查询，并用 `static_assert` 检查。按 C++11，`constexpr` 非静态成员函数隐式为 `const`，且当时的 `constexpr` 函数不能返回 `void`，所以改变状态的 `set_` 函数不应声明为 `constexpr`；C++14 放宽了相关规则，不能把 C++11 限制推广到所有版本。书中的 `Data` 含 `std::string`，在 C++11 中不是字面值常量类；较新标准对 `string` 的 constexpr 支持有所变化。

## 7.56–7.57：静态成员

静态数据成员属于类，所有对象共享一份；静态成员函数没有 `this`，不能直接访问某个对象的非静态成员。[ex7_53_58.cpp](ex7_53_58.cpp) 的 `Account` 共享利率而各自保存余额，演示类外定义和使用。

## 7.58：静态成员声明和定义

按本书 C++11：非常量浮点静态成员 `rate` 不能以题目写法在类内初始化，应在类内声明、类外定义并初始化；类内可给整型常量 `vecSize` 提供常量表达式初值，若被 ODR 使用还需类外定义；`vec(vecSize)` 不是合法的静态数据成员初始化声明，应先在类内声明 `static vector<double> vec;`，再在类外定义并用 `vecSize` 构造。示例见 [ex7_53_58.cpp](ex7_53_58.cpp)。C++17 的 inline 静态成员另有不同规则。
