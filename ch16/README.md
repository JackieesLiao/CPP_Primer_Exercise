## 16.31–16.36 删除器与模板实参推断

- **16.31** `unique_ptr<int, DebugDelete>` 的类型包含删除器类型。析构时调用的 `DebugDelete::operator()<int>` 在编译期就能确定。编译器看到定义时可以直接内联函数体，是否内联取决于优化。
- **16.32** 编译器把调用实参的类型和函数形参类型匹配，从中推断未显式指定的模板实参。同一模板参数从多个形参推断时，结果必须一致。
- **16.33** 推断允许有限的 `const` 调整，以及非引用形参对应的数组到指针、函数到指针转换。按值传递还会忽略顶层 `const`。推断不会靠数值转换来统一两个互相冲突的类型。
- **16.34** `compare("hi", "world")` 推断出两个不同长度的数组，调用不合法。`compare("bye", "dad")` 的两个字面量长度相同，`T` 是 `char[4]`，调用合法。原函数体中的 `<` 比较的是退化后的指针，不能用来比较文本内容。
- **16.35** `calc(c, 'c')` 推断 `T = char`，`calc(d, f)` 推断 `T = double`。两者的第二个形参固定为 `int`，因此可以做普通转换。`fcn(c, 'c')` 推断 `T = char`，`fcn(d, f)` 则因 `double` 与 `float` 冲突而失败。
- **16.36** `f1(p1, p2)` 推断 `T = int*`，`f1(cp1, cp2)` 推断 `T = const int*`。混合调用 `f1(p1, cp1)` 推断冲突。`f2` 分别推断两个形参，三组调用依次得到 `(int*, int*)`、`(const int*, const int*)` 和 `(int*, const int*)`。

## 16.37–16.39 显式模板实参

- **16.37** `std::max(3, 4.5)` 推断冲突。指定 `std::max<double>(3, 4.5)` 后，`int` 可转换为 `double`，结果为 `4.5`。把结果按值保存，避免引用绑定到调用中的临时对象。
- **16.38** `make_shared<T>` 的函数实参只用于构造对象，无法从中推断对象类型 `T`。`make_shared<std::string>(4, 'x')` 指定了要构造的类型，并把两个参数转发给字符串构造函数。
- **16.39** `compare<std::string>("hi", "world")` 把两个形参确定为 `const std::string&`，两个字面量可隐式构造成字符串，按字典序比较得到 `-1`。

[ex16_37_39.cpp](ex16_37_39.cpp) 可以独立运行，依次输出 `4.5`、`xxxx` 和 `-1`。以上九题见书页 600、603–604（PDF 页 626、629–630）。

## 16.63–16.67 count 与特化

[ex16_63_65.cpp](ex16_63_65.cpp) 的模板 `count_values` 对 `vector<int>` 计数 2 出现 3 次；16.64 的非模板重载对 `vector<const char*>` 用 `strcmp` 比较（否则比较的是指针）。16.65 的显式特化写法为 `template <> int count_values<const char *>(const std::vector<const char *> &, const char *const &);`，但一旦存在非模板重载，特化版本永远不会被选中，因此本仓库用重载实现并在 README 记录特化形式。16.66/16.67 讨论了特化与重载的选择。
