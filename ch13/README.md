# 第 13 章：拷贝控制

已核对并整理 13.1–13.58（书页 440–522 / PDF 页 466–548）。知识复习见 [复习提纲](REVIEW.md)。

## 13.1–13.4 拷贝控制的发生时机

拷贝构造函数在"以同类对象初始化新对象"时调用：`Sales_data s2(s1)`、按值传参、按值返回非移动构造类型。13.2 的 `Sales_data(const Sales_data &s)` 不接受引用，拷贝构造又需要拷贝实参，无限递归，无法编译。13.3 中 `StrBlob` 的合成拷贝构造复制 `shared_ptr`（引用计数加一，两份共享数据），`StrBlobPtr` 复制 `weak_ptr` 与下标。13.4 中 `Point` 的 `operator=` 在赋值时执行。

## 13.5–13.11 HasPtr 的拷贝控制

[ex13_05_08_11.cpp](ex13_05_08_11.cpp) 给出值语义的 `HasPtr`：拷贝构造分配新串（13.5），赋值先分配后释放保证自赋值安全（13.8），析构释放（13.11）。程序演示拷贝、赋值与自赋值后三个对象各自持有独立副本。

## 13.9–13.12 析构函数

析构函数释放资源并销毁成员，合成版本按成员声明逆序销毁。13.10：`shared_ptr` 成员的合成析构会递减引用计数，指针成员的合成析构什么也不做（泄漏）。13.12 的代码片段中每个对象离开作用域各调用一次析构。

## 13.13–13.17 拷贝的观察

[ex13_13_16.cpp](ex13_13_16.cpp) 用静态计数器给每个 `Numbered` 编号并跟踪拷贝：`a`、`b = a`、`c = b` 分别得 1、2、3；按值传参时拷贝构造一次（得 4、5、6），按引用传参不拷贝（仍见 1、2）。13.14 的静态编号已并入本类；13.15 若拷贝构造沿用原编号，输出将全是源对象的编号；13.17 的三版程序分别演示了默认拷贝、自编号拷贝与引用传递。

## 13.18–13.19 Employee 的唯一编号

[ex13_18.cpp](ex13_18.cpp) 中静态计数器让每个员工拿到 1、2、3 的编号；拷贝或赋值会复制或改写编号、破坏唯一性，因此两者都被 `= delete`。

## 13.20–13.25 需要哪些拷贝控制

13.20：仅含 string 成员的类用合成版本即可；持有裸指针资源的类必须自定义。13.21：我们的 HasPtr 已按值语义实现。13.22 的 copy-and-swap 写法见 [ex13_30_31.cpp](ex13_30_31.cpp)。13.23 的两个赋值版本一处先删后拷（自赋值出错）、一处忘记释放旧内存。13.24：没有析构会泄漏，没有拷贝构造会共享同一字符串导致双重释放。13.25：`resize` 的元素用值传递（可能来自临时对象，不宜 const 引用）；StrBlob 的成员是 `shared_ptr`，合成版本足够。

## 13.26–13.28 更多类

StrBlob 本就持有 `shared_ptr`，拷贝共享数据符合预期。13.27 的引用计数版 HasPtr 见 [ex13_27.cpp](ex13_27.cpp)：三个使用者计数为 3，离开内层块后回落到 3；释放只发生在最后一个使用者析构时。13.28 的 TreeNode/BinStrTree 需要深拷贝：左子树、右子树逐层递归复制，析构递归释放，赋值先拷贝再释放。

## 13.29–13.32 swap

13.29：`swap(HasPtr&, HasPtr&)` 内的 `swap(left.value, right.value)` 通过 `using std::swap` 解析为指针交换，参数是引用而不是 HasPtr 本身，不会回到 HasPtr 的 swap，因此不递归。13.30 的 swap 交换两个指针。[ex13_30_31.cpp](ex13_30_31.cpp) 用它配合 `operator<` 对 `vector<HasPtr>` 排序（13.31），交换指针远比拷贝字符串便宜。13.32：copy-and-swap 的类已在赋值中获得移动路径，另行定义 swap 的收益有限。

## 13.33–13.38 Message 与 Folder

[Message.h](Message.h) 与 [Folder.h](Folder.h) 实现双向同步：`save`/`remove` 同时更新两侧（13.34）；拷贝消息把副本登记进源消息所在的每个文件夹，赋值先从旧文件夹撤下再登记（13.35）；Folder 的拷贝、赋值、析构对称（13.36）；`add_msg`/`rem_msg` 是 13.37 的接口。33 题的答案是参数应为 `Folder&`：指针允许为空，且无法表达"必须有文件夹"的意图。`swap(Message&, Message&)`（13.38 的修正版）把两条消息从各自文件夹撤下、交换内容与登记表、再重新登记——书中的写法只交换指针集合而不通知文件夹。运行 [ex13_34_37.cpp](ex13_34_37.cpp) 可见拷贝、赋值、文件夹拷贝与删除后两侧计数始终一致。

## 13.39–13.43 StrVec

[StrVec.h](StrVec.h) 用 `elements/first_free/cap` 三指针与 `std::allocator` 管理存储。容量用完时，`append` 先在新存储中构造追加的元素，再移动旧元素，因此 `v.push_back(v[0])` 也能安全扩容。13.40 的 `initializer_list` 构造按精确大小分配。[ex13_39_40.cpp](ex13_39_40.cpp) 展示容量 1→2→4、列表构造和拷贝。13.41 中教材的 `construct(destination++, std::move(*element++))` 使用两个指针的旧值作为实参。本实现以索引标记已分配的位置，成功构造后才更新存储边界。13.43 的 `free` 用 `for_each` 加 lambda 逐个销毁元素。[ex13_42.cpp](ex13_42.cpp) 把第 12 章的文本查询搬到 [StrVecTextQuery.h](StrVecTextQuery.h)，输出与第 12 章版本一致。

## 13.44–13.50 自己的 String

[String.h](String.h) 以 `allocator<char>` 管理带终止符的字符数组，拷贝、赋值与移动都打印踪迹。13.45：`&r` 若绑定的表达式是左值就是左值引用，`&&r` 绑定右值。13.46 的十个声明里，字面量、函数返回值、算术表达式是右值（`(a)`、`(b)`、`(e)`…），变量与解引用是左值。[ex13_44_48.cpp](ex13_44_48.cpp) 的核心输出是 `vector<String>` 的增长：1→2 移动一个元素，2→4 移动两个（13.48/13.50）——因为移动构造标记 `noexcept`，vector 才敢用移动代替拷贝。

## 13.49–13.55 移动操作

13.49 的移动构造/赋值：StrVec 窃取三指针并把源置空（[StrVec.h](StrVec.h)），String 交换指针（[String.h](String.h)），Message 的移动与拷贝类似但需要同步文件夹。13.51 中接受 `unique_ptr` 形参的函数只能由右值调用，因为拷贝被删除、移动可行。13.52：按值赋值参数在左值时经拷贝构造、右值时经移动构造，进入函数体后只需交换。13.55 的 StrVec 右值 `push_back(std::string&&)` 已加入 [StrVec.h](StrVec.h)，直接 `std::move` 构造新元素，避免整串复制。

## 13.53–13.58 引用限定与移动的取舍

13.53 的成员式移动赋值必须先判断自赋值（`this != &rhs`），并处理 `ps` 可能同时出现在两侧的别名问题；与 copy-and-swap 相比并未更高效。13.54 的友元版 `operator=(HasPtr&&)` 只做一次交换。13.56 的 `return ret.sorted()` 中 `ret` 是左值，再次匹配 const & 重载，无限递归；13.57 的 `return Foo(*this).sorted()` 构造临时对象成为右值，命中 && 版本。[ex13_58.cpp](ex13_58.cpp) 同时调用两个版本：lvalue 走 `sorted() const &` 并保持原对象不变，右值走 `sorted() &&` 原地排序。
