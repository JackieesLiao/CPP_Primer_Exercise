## 9.1 选择容器

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 固定数量的单词逐个插入并保持字典序 | `list` 是合理选择 | 定位插入点仍需线性查找，但找到位置后插入不移动其他元素；数量小或缓存局部性重要时 `vector` 也可能更快，需测量。 |
| 尾部插入、头部删除 | `deque` | 两端操作高效，不需要 `vector` 头部删除时移动后续元素。 |
| 读取未知数量整数，排序后打印 | `vector` | 尾部追加方便，支持随机访问和 `std::sort`，连续存储通常有较好的局部性。 |

固定数量并不意味着必须选 `array`：本题明确比较 `vector`、`deque` 和 `list`，且按顺序插入可能需要改变当前元素数量。

## 9.2 嵌套容器

`std::list<std::deque<int>> values;` 定义一个 list，其元素各自是 `deque<int>`。需要包含 `<list>` 和 `<deque>`。

## 9.3 迭代器范围的约束

两个迭代器必须指向同一容器的元素或尾后位置，并且可以从第一个通过有限次递增到达第二个。范围是左闭右开 `[first, last)`；相等表示空范围，尾后迭代器不能解引用。

## 9.4–9.5 搜索范围

[ex9_04_05.cpp](ex9_04_05.cpp) 分别提供返回 `bool` 的 `contains` 和返回迭代器的 `find_value`。未找到时返回传入的 `last`；调用者必须先比较再解引用。程序的示例容器是 `2 4 6`。

## 9.6 list 迭代器比较

`list` 迭代器是双向迭代器，不提供 `<`。应使用 `iter1 != iter2`，并确保循环体在有效范围内推进迭代器。它们之间可以递增到达的前提不可省略。

## 9.7–9.8 容器类型成员

索引 `vector<int>` 元素使用 `vector<int>::size_type`。只读 `list<string>` 用 `list<string>::const_iterator`；需要经迭代器修改元素时使用 `list<string>::iterator`。

## 9.9–9.10 begin 与 cbegin

非 `const` 容器的 `begin()` 返回可写迭代器，常量容器的 `begin()` 返回常量迭代器；`cbegin()` 总返回常量迭代器。因此题中 `it1` 是 `vector<int>::iterator`，`it2`、`it3`、`it4` 都是 `vector<int>::const_iterator`。

## 9.11 六种 vector 初始化

```cpp
std::vector<int> empty;             // 空
std::vector<int> copy(original);    // 与 original 相同
std::vector<int> copy2 = original; // 与 original 相同
std::vector<int> range(first, last); // 复制 [first, last)
std::vector<int> values{1, 2, 3};  // 1、2、3
std::vector<int> zeros(3);         // 三个 0
std::vector<int> sevens(3, 7);     // 三个 7
```

这里分别展示默认、复制、范围、列表、指定数量和数量加初值六类方式；复制初始化还展示了另一种写法。花括号优先匹配列表初始化：`{3, 7}` 是两个元素，不是三个 7。

## 9.12 容器拷贝与迭代器范围构造

直接拷贝要求容器类型和元素类型相同；迭代器范围构造可来自不同容器，只要范围有效且元素可转换为目标元素类型。范围构造也可只复制一段。

## 9.16：比较 list 和 vector

容器类型不同，不能直接用容器的 `==`。示例先比较长度，再用 `std::equal` 比较两个范围对应的元素。先比较长度可确保 C++11 的三迭代器重载不会越过第二个范围。

## 9.17：关系比较的约束

两个容器必须是支持 `<` 的相同容器类型，元素类型也应相同且支持相应的元素比较。顺序容器按字典序比较：首个不同元素决定结果；若一个序列是另一个的前缀，较短的序列较小。

## 9.21：vector 的 insert 返回值

在循环中执行 `iter = container.insert(iter, word)`，然后将下一项继续插入该位置之前，得到的顺序与 `push_front` 一样是输入的逆序。`vector` 的插入可能使旧迭代器失效，因此必须使用返回值；循环中不能缓存失效的 `end()`。

## 9.22：在 vector 中点之前插入

原程序在插入后继续使用原来的 `iter` 和 `mid`，而插入可能使它们失效；即使未重新分配，插入位置及其后的迭代器也失效。另外，循环还必须推进。下面用索引表示位置，并让 `mid` 始终指向原后半段的开头；假设 `2 * some_val` 可以由 `int` 表示。

```cpp
std::size_t index = 0;
std::size_t mid = values.size() / 2;
while (index < mid)
{
    if (values[index] == some_val)
    {
        values.insert(values.begin() + index, 2 * some_val);
        ++mid;
        index += 2;
    }
    else
    {
        ++index;
    }
}
```

每次从当前 `begin()` 和索引计算插入位置，不保留插入前的迭代器。匹配时跳过新元素与已检查的原元素。

## 9.23：单元素容器的首尾

在书中保证容器非空的前提下，大小为 1 时，`*c.begin()`、`c.front()`、`*--c.end()` 和 `c.back()` 都指向同一个元素；若接收变量使用 `auto` 而不是引用，它们是这个元素的值的副本。

## 9.24：空 vector 的元素访问

对空容器，`at(0)` 会抛出 `std::out_of_range`；`operator[]`、`front()` 和解引用 `begin()` 均不满足前提，行为未定义。不要通过实际执行未定义行为来验证；先用 `empty()` 检查。

## 9.25：erase 区间的边界

`erase(first, last)` 删除半开区间。如果两个有效迭代器相同，范围为空，不删除元素并返回 `last`。如果两者都是尾后迭代器，同样是合法空范围；若仅 `last` 是尾后迭代器，则删除从 `first` 到末尾的元素。不能把尾后迭代器作为单元素 `erase(pos)` 的位置。

## 9.26：用 erase 删除奇偶元素

[ex9_26_28.cpp](ex9_26_28.cpp) 将题目给定数组复制到 `list` 和 `vector`，分别删除偶数与奇数。删除后采用 `erase` 的返回值；未删除时才递增。特别是 `vector` 删除会使删除点及之后的迭代器失效，不能再用旧值。

## 9.27：forward_list 删除奇数

同一源码维护前驱和当前迭代器：删除时执行 `current = values.erase_after(previous)`，前驱不动；保留时两者一起前进。`before_begin()` 可以作为首元素的前驱。

## 9.28：在匹配字符串之后插入

同一源码查找第一个匹配项，找到后用 `insert_after` 插入；没找到则在最后一个元素后追加。空链表时保存的前驱是 `before_begin()`，因此追加也适用。

## 9.29：resize 的结果

假设原有 25 个元素，`resize(100)` 保留原来 25 个并在末尾追加 75 个值初始化元素；如果元素是 `int`，新增值为 0。接着 `resize(10)` 删除下标 10 及其后的 90 个元素，保留最初的前 10 个。

## 9.30：单参数 resize 的元素要求

当调用需要增大容器时，单参数 `resize(n)` 需要能够默认插入元素；已有元素还必须满足该容器和实现对移动、插入操作的要求。若元素类型不能默认构造，可使用 `resize(n, value)` 提供初值，前提是该类型满足相应复制插入要求。

## 9.31：为 list 和 forward_list 改写循环

书中版本使用的 `iter += 2` 要求随机访问迭代器，而两种链表都不支持。`forward_list` 还通过前驱使用 `insert_after`、`erase_after`。见 [ex9_31.cpp](ex9_31.cpp)：对偶数删除、对奇数复制，并保持前驱与当前迭代器的关系。

## 9.32：在一次 insert 调用中递增迭代器

`vi.insert(iter, *iter++)` 同时把 `iter` 用作插入位置并递增它，依赖函数实参的求值先后；C++11 中对同一对象的未排序读写会导致未定义行为。即使在较新的求值规则下也不应依赖参数顺序。将取值、插入和推进拆为独立语句，并使用 `insert` 返回的新迭代器。

## 9.33：忽略 insert 返回值

`vector` 插入会使插入位置及其之后的迭代器失效，发生重新分配时所有迭代器都失效；继续使用原来的 `begin` 属于未定义行为。应保存 `begin = v.insert(begin, 42)` 后再按需要推进。未定义行为可能表现为崩溃、错误输出或看似正常，不应依赖某次运行结果。

## 9.34：缺少花括号的循环

书中 `while` 后只有紧随的 `if` 是循环体，后面的 `++iter` 位于循环之外。遇到偶数时迭代器不前进而无限循环；遇到奇数时重复在当前位置插入副本，容器持续增长，最终可能耗尽资源或抛出异常。实际验证应设置严格限制，避免运行原始无限循环。

## 9.35–9.37：size 与 capacity

`size()` 是已存在元素数量；`capacity()` 是无需重新分配时可容纳的元素数量，因此 `capacity() >= size()`。`list` 按节点分配，没有 vector 式连续预留容量；`array` 的大小固定并属于类型，也无需提供可增长的容量接口。

## 9.39：reserve 与 resize

## 9.40：不同输入量下的容量

256、512、1000、1048 个词执行 `resize` 后的大小分别是 384、768、1500、1572。前两种大小不超过初始 `reserve(1024)` 保证的容量，因此不会因这次 `resize` 必须重新分配；后两种只保证最终容量至少等于相应大小。最终确切容量取决于实现，也取决于追加阶段是否扩容，不能断言一定是某个数。
